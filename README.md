# 正则表达式构造流水线可视化

一个用于形式语言与自动机课程的浏览器教学工具，把

```
正则表达式 ──Thompson──▶ ε-NFA ──子集构造──▶ DFA ──Hopcroft 最小化──▶ 最小化 DFA
```

这整条流水线在页面上**一步步演出来**，每一步都看得见，并且可以在三台机器上
回放同一个测试串，直观验证"**同一正则、同一串，三台机器接受结论必然一致**"这条主线。

所有构造与判定（解析、Thompson、子集构造、Hopcroft、模拟、语言对拍）都在后端完成，
前端只负责展示和交互，不另算一套。

## 功能一览

- **正则输入**：连接（并列）、选择 `|`、闭包 `*`、正闭包 `+`、可选 `?`、括号分组、
  字符类 `[a-z]`、常见转义 `\d \w \s \n \t`，空分组 `()` 表示 ε。
- **三段逐步演示**，每段都支持「上一步 / 播放 / 暂停 / 下一步 / 一键跑完 / 拖动进度」：
  1. **Thompson 构造**：每个算子的小片段依次拼到已有 NFA 上，当前片段橙色高亮。
  2. **子集构造**：逐步求 ε-closure 与 move；左侧 DFA 图与右侧**子集对照表**同步高亮
     当前展开的子集、新发现的状态和待处理队列。
  3. **Hopcroft 最小化**：在原 DFA 上按等价类染色，逐组演示"为什么被拆开"
     （读某个符号后落进不同的组），最后一帧折叠成最小化 DFA，并给出
     每个最小化状态合并了哪些原状态。
- **状态图**：状态圆圈、接受态双圈、初态黑点+箭头、带标签有向边；
  支持滚轮缩放与拖拽平移，状态很多时可滚动查看。
- **测试串回放**：三台机器各跑一遍，逐字符高亮走过的状态/边与活动状态集，
  顶部字符条同步推进；结论横幅显示三机是否一致。
- **内置示例**：标识符、带小数的数字、字符串字面量、三段式电话号码、
  `(a|b)*abb`、可选与正闭包，一点即填（含推荐的接受/拒绝测试串）。
- **友好错误**：括号不配对、算子缺操作数、字符类区间非法等都返回带位置的错误，
  输入框下方用 `^` 标出列。
- **答案对拍（助教批作业）**：左填标准答案、右填学生答案，后端直接判定两条正则
  语言之间的四种关系之一——**两边等价 / 左真包含于右 / 右真包含于左 / 互不包含**；
  只要某方向差集非空就给出该方向的反例，互不包含时两个方向各一条。
  - 反例是差集里 **shortlex 最小**（先比长度，同长再按字符码点逐位比较）的那条，
    同一对输入无论调用多少次、左右怎么交换都完全一致；空串反例返回 `witness: ""`，
    与"该方向无反例"的 `witness: null` 严格区分。
  - 判定在**两边字母表的并集**上进行，并把三段演示里隐式的死状态**显式补出**
    参与乘积构造、在图上画成灰色虚线的 † 状态。
  - 对拍过程逐步演示：两台机器同步运行的**组合状态图**，每个状态标明左右分量，
    四类接受性（两边都接受 / 仅左接受 / 仅右接受 / 两边都不接受）用颜色区分，
    当前展开 / 新发现 / 待处理队列分别高亮，支持播放与一键跑完。
  - 反例旁的按钮把该串送进回放：左右各自在自己的 NFA / DFA / 最小化 DFA
    三台机器上走同一条串，亲眼看到一边三台一致接受、另一边三台一致拒绝。
  - **批量判定**：一条标准答案配最多 30 条学生答案（每行一条），按提交顺序逐条
    返回结论与反例；超限整批拒绝；单条语法/规模出错只拖累它自己那一条（带原因与列号）。
  - 组合状态数有硬上限（400），超限立即报 `422 product_limit`，请求不会挂死。

## HTTP 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| `GET` | `/api/health` | 健康检查 |
| `GET` | `/api/examples` | 内置示例列表 |
| `POST` | `/api/construct` | 入参 `{ "regex": "..." }`，返回三机完整结构与全部逐步数据 |
| `POST` | `/api/simulate` | 入参 `{ "regex": "...", "input": "..." }`，返回三机轨迹与 `agreement` |
| `POST` | `/api/compare` | 入参 `{ "left": "标准答案", "right": "学生答案" }`，返回四种关系之一、两个方向各一条 shortlex 最小反例、两侧补全死状态的完整 DFA、乘积组合状态图与全部逐步数据 |
| `POST` | `/api/compare-batch` | 入参 `{ "reference": "...", "students": ["..."] }`（≤30 条），按提交顺序逐条返回；单条错误隔离在该条内 |

非法正则返回 `400 { "error": "...", "position": 12 }`，`position` 为 0 基列号。
`/api/compare` 的语法错额外带 `"side": "left" | "right"` 标明是哪一边；
组合状态超过 400 个时返回 `422 { "error": "...", "code": "product_limit" }`。
对拍响应里反例对象形如 `{ "exists": true, "witness": "bb", "length": 2, "productState": 5 }`：
无反例时 `exists:false, witness:null`，空串反例时 `exists:true, witness:""`。
`/api/compare-batch` 超过 30 条或字段非法时整批 `400`；标准答案非法整批 `400`；
学生答案某条出错只在该条结果里给 `ok:false` 与错误原因/列号，其余照常出结论。

## 本地开发

需要 Node.js 20+。

```bash
npm install          # 安装两个 workspace 的依赖

# 终端 1：后端（tsx 热更新，:3000）
npm run dev:server

# 终端 2：前端 Vite 开发服务器（:5173，/api 代理到 3000）
npm run dev:web
```

打开 http://localhost:5173 。

## 生产构建与运行

```bash
npm run build        # tsc 编译后端 + vite 打包前端到 frontend/dist
npm start            # http://localhost:3000，页面与接口同端口
```

## Docker 一体构建

```bash
docker build -t regex-pipeline-viz .
docker run --rm -p 3000:3000 regex-pipeline-viz
# 或
docker compose up --build
```

容器起来后访问 http://localhost:3000 ，前端静态页面与 `/api/*` 接口由同一个
Node 进程对外提供。

## 测试

```bash
npm test             # backend workspace 下的 Vitest
```

`consistency.test.ts` 对 20+ 条覆盖各类算子的正则，穷举字母表上的短串
（二元字母表到长度 6），逐条断言：

1. NFA 的结论等于直接在 AST 上递归的**参考语义**；
2. DFA 与 NFA 一致；
3. 最小化 DFA 与 DFA 一致；
4. 最小化结果再最小化是幂等的。

这把"三台自动机对同一测试串判定一致"这条正确性主线锁死在了自动化测试里。
`compare.test.ts` 另外钉住：

1. 助教手算样例的四种关系与每条反例（含空串反例 `witness:""` 与无反例
   `witness:null` 的区分、交换左右后方向对调且反例串不变）；
2. 每条给出的反例放到两侧各自的三台机器上模拟，恰好一边接受一边拒绝；
3. 在 14 对小字母表正则上，用长度 6 以内的穷举串交叉核对：判定结论与穷举一致，
   给出的反例正是穷举按 shortlex 序排第一的那条；
4. 批量请求里单条语法/规模出错不拖累其他条；组合状态超 400 上限明确报错。

## 教学实现上的几点取舍

- **Hopcroft 用朴素划分细化**：与教科书"工作队列 + 反向边"的优化版结果完全等价
  （都得到最粗同余划分），但每轮把所有组重新检查一遍，拆分过程线性、可读，
  更适合课堂逐步演示。
- **不显式画死状态（三段演示）**：子集构造中没有任何 NFA 状态可达的符号不产生转移
  （相当于落入隐式死状态），保持图面简洁；模拟时据此判定拒绝。**答案对拍是个例外**：
  判定在两边字母表并集上进行，乘积构造前会给每台最小化 DFA 显式补一个死状态
  （处处有转移、死状态自环），并在对拍页把它画成灰色虚线的 † 状态，
  学生能直观看到"读到对方字母表里的符号时在哪一步分岔"。
- **反例的确定性**：乘积 BFS 按码点序枚举符号，组合状态第一次被发现时的到达串
  天然是 shortlex 最小串；每个非等价的接受类别只取 BFS 中第一个状态，
  所以同一对输入连判任意次、左右任意交换，反例串都完全一致。
- **状态编号稳定**：NFA 状态按构造后序编号，DFA 状态按子集发现顺序编号，
  最小化状态按"组内最小编号"编号，逐步播放时坐标不跳动。
- **字符类标签压缩**：`[a-zA-Z0-9_]` 这类在图上会把连续区间合并显示为 `0-9`、
  `A-Z`、`_`、`a-z`，但底层仍按单符号边参与构造与模拟。
